# 腰有据 · UI 设计稿说明（整理自 Figma《UI 界面设计 V0.1》）

设计稿以本目录的 PNG 为准，逐页还原布局、颜色、字号、间距、图标和文案。
- `00-spec.png`：封面、阅读地图、信息架构、设计规范
- `app/A01.png`–`app/A18.png`：App 端（Android / H5），设计宽度 375，图片按 2 倍导出（750 宽）
- `web/W01.png`–`web/W08.png`：Web 端，设计宽度 1440，按 1 倍导出
- `admin/B01.png`–`admin/B12.png`：后台管理系统，设计宽度 1440，按 1 倍导出

示例数据均为演示，不涉及真实用户。

## 设计基调
克制、可信、易读。不用制造紧张感的大面积红色，不用“AI 医生”拟人形象；每条解释可见来源，每个未知项显式标出。

## 状态标签（三端语义完全一致）
已确认、尚未确认、有冲突、未经核实、报告原文、自述、系统生成、已审核 v2、已下线 · 更正中、不作诊断。

规则：
- 未回答显示“尚未确认”，不能显示“无”。
- 报告未描述显示“报告未提及”，不能显示“已排除”。
- 系统生成的内容带版本号，不标为事实来源。

## 组件与尺寸
- 按钮：主按钮、次按钮、柔和、危险 / 就医；芯片：已选、未选、跳过；输入框；提示条三种（信息提示、提醒、就医提示）。
- 最小点击区域 44×44。
- 圆角：卡片 12，按钮 10，标签 4。
- 页面边距：移动端 16，桌面端 24–40。

## 信息架构
- 用户侧固定四个入口加“我的”：当前情况（首页）、问与解释、病程、复诊准备、我的。社区不占首屏。
- 紧急就医提示在任意位置可达，不被登录、付费、上传或长问卷阻断。
- 后台面向五类角色：运营编辑、临床审核、技术、合规、超级管理。

## 页面清单
### App 端（375）
| 编号 | 页面 | 设计要点 |
|-|-|-|
| A01 | 启动 · 登录与授权 | 手机号验证码登录；单独同意处理敏感健康信息；紧急求助入口不被登录阻断 |
| A02 | 当前关键变化确认（R01/R03） | 低负担录入；缺失不默认阴性；红旗项优先于其他流程 |
| A03 | 就医提示（R03 安全与范围流程） | 红旗信号直接提示；不被注册、付费、上传或长问卷阻断；停止个性化分析 |
| A04 | 选择主要困惑 | 用户主动选择困扰点与解释方式；按需调整长度、节奏与形式 |
| A05 | 录入报告与既有医嘱（R02） | 优先粘贴文字或清晰文本提取；记录来源类型与日期；可跳过 |
| A06 | 核对结构化信息（R01/R02） | 来源、时间、核实状态可见；冲突项须确认；缺失不默认阴性 |
| A07 | 一页理性分析（R04 证据化回答） | 固定五段结构；每条解释带来源；缺失即未知、不补写概率；反馈不自动入库 |
| A08 | 原文对照（R02） | 解释与原文逐句对应；高亮引用；报告未提及 ≠ 已排除 |
| A09 | 问与解释（R03/R04） | 基于当前上下文；引用来源；越界问题明确不答并转为复诊问题；反复求保证时稳定解释并结束本轮 |
| A10 | 病程时间线（R05） | 按事件记录；区分自述 / 报告原文 / 医生记录；用户可纠正、删除；变化图不暗示影像恶化 |
| A11 | 记录今天（R01/R05） | 以生活任务组织记录；允许跳过；缺失不默认阴性；不复用昨日答案 |
| A12 | 复诊摘要预览与导出（R05） | 固定六段；区分自述 / 原文 / 医生记录；未核实项保留；用户预览后自主导出 |
| A13 | 审核内容库（R06） | 8–12 个概念视频 / 图文；适用范围、版本、审核记录、下线开关；推荐理由可见 |
| A14 | 首页 · 当前情况（主 Tab） | 待确认项优先；最新分析摘要；快捷入口；复诊倒计时；社区不占首屏 |
| A15 | 视频详情（R06） | 适用 / 不适用范围、审核版本与依据、字幕与文字替代、复述任务检验理解 |
| A16 | 反馈与错误举报（R07） | 自动附带分析 / 模型 / 内容版本；分类举报；单条授权查看；反馈不自动入库 |
| A17 | 我的 · 数据与授权 | 同意记录可查可撤回；导出与删除；身份与分析分离；服务边界可见 |
| A18 | 服务不可用回退 | 模型 / 检索 / 来源校验失败时明确说明；保留已审核资料与摘要功能；不无限重试与重复计费 |
