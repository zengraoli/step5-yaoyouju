## 三端状态标签一致性

三端 `StatusTag` 组件定义逐项比对：10 个状态键（已确认 / 尚未确认 / 有冲突 / 未经核实 /
报告原文 / 自述 / 系统生成 / 已审核 v2 / 已下线 · 更正中 / 不作诊断）文案与色调完全一致；
主题变量（色彩令牌 17 项）三端一致（后台额外使用 #12202b 作为登录页 / 侧边栏深色，
与 B01 设计稿一致）；圆角、字号、间距令牌一致。

## 走查中发现并修复的问题

1. **CORS 未开启（阻塞性）**：App / Web / Admin 均跨域访问 3200，浏览器拦截全部请求
   （Node 侧联调无 CORS 所以此前未暴露）。已在 `server/src/main.ts` 开启 CORS
   （origin 反射 + Bearer 头），修复后三端页面均能加载真实数据。
2. **种子摘要为旧格式**：`followup_summary.content.sections[].items` 为字符串数组，
   服务端已归一为 `{text, source, verify_status}` 对象，导致 A12 / W06 摘要全部显示
   「尚未确认」。已更新 `server/src/db/seed.ts` 为对象格式并带来源与核实状态。
3. **GET 请求携带 body（浏览器报错）**：Web / Admin 请求封装对 GET 也序列化 body，
   `fetch` 直接抛错并被吞掉，表现为表格空白。已改为 GET 参数拼查询串（`web|admin/src/api/request.ts`）。
4. **Web 路由缺失**：`/analysis`、`/contents` 路由在 T27 时未成功插入，W03 访问 404。
   已补齐路由与视图。
5. **后台刷新丢失身份**：刷新后 `admin` 为空导致侧边栏仅剩「仪表盘」、权限判断失效。
   已在 AdminLayout 挂载时按令牌拉取 `/admin/auth/me`，失效则回到登录页。
6. **后台硬编码统计**：B06「帮助类型反馈 186」为写死数据，已改为按 7 天窗口与
   help_type 从接口计算。
7. **Swagger DTO 重名**：admin-cases 与 admin-contents 的 `ReasonDto`、admin-evidence 与
   evidence 的 `EvidenceDocBody` 重名导致 `/api-docs` 报错，已重名修复。
8. **App 页面外背景**：`html/body` 未设置背景色，截图出现黑色区域，已在全局样式补齐。
