# 腰有据 · 腰痛理解与复诊助手（演示实现）

帮助腰痛用户看懂检查报告、整理病程、准备复诊的助手：用户录入当前变化和报告，系统生成“一页理性分析”（已知 / 解释 / 未知 / 下一步 / 视频），并整理成复诊摘要带给医生。产品**不作诊断**。

本项目按设计方提供的材料实现：
- UI 设计稿：`docs/design/`（38 页，App 18 / Web 8 / 后台 12），逐页还原
- 系统设计：`docs/system-design.md`（架构、主流程、ER、内容审核状态机、一页分析时序）

## 仓库结构
```
server/   API 服务 + AI 任务 Worker
app/      用户端 App（uni-app，H5 / Android）
web/      用户端 Web
admin/    后台管理系统
docs/     需求、系统设计、设计稿
```

## 技术栈
| 子项目 | 技术栈 |
|-|-|
| server | Node.js 24 + TypeScript + NestJS + SQLite（驱动与 ORM 自选，必须能在 Windows + Node 24 上直接安装运行） |
| app | uni-app（Vue 3 + Vite + TypeScript）；以 H5 构建验收，Android 打包可选 |
| web | Vue 3 + Vite + TypeScript + Pinia + Vue Router |
| admin | Vue 3 + Vite + TypeScript + Pinia + Vue Router |

web 和 admin 可以自选组件库，但最终外观以设计稿为准。

## 演示实现的简化
原设计中的基础设施在本项目中按下表替代，模块边界和业务规则保持不变：

| 原设计 | 本项目 |
|-|-|
| PostgreSQL 业务库 | SQLite 文件 `server/data/app.db` |
| 身份隔离库（字段加密） | 独立 SQLite 文件 `server/data/identity.db`；手机号、姓名用 AES-256-GCM 加密，密钥从环境变量读取，仓库只提供 `.env.example` |
| Redis Streams 任务队列 | SQLite 任务表；Worker 为独立进程 `npm run worker`，轮询消费 |
| pgvector 医学证据向量库 | 证据片段表 + 本地检索（关键词或本地计算的向量均可），只在证据库内检索 |
| 大模型服务商 | 可替换的适配层接口；默认使用本地模拟实现，按模板和证据片段生成，不调用任何外部服务 |
| OCR | 模拟实现，返回示例文本；主路径是粘贴文字 |
| 短信 | 验证码固定为 `123456`，只写日志（手机号脱敏） |
| 后台 TOTP | 演示固定码 `123456` |
| 对象存储 / 视频 CDN | 本地文件与本地占位图，不引用外部资源 |
| 复诊摘要导出 PDF | 文本复制必做；PDF 通过浏览器打印生成；图片导出可选 |

## 产品红线（所有端都必须遵守）
1. 不作诊断，不给用药、手术建议；越界问题明确不答，可转为复诊问题。
2. 缺失信息显示“尚未确认”，不能默认为阴性或“无”；报告未描述显示“报告未提及”，不能显示“已排除”。
3. 命中红旗信号时立即显示就医提示，不被登录、付费、上传或长问卷阻断，并停止个性化分析。
4. 每条解释都能看到来源；系统生成的内容带版本号，不标为事实来源。
5. 反馈与举报不自动进入训练或内容库。
6. 示例数据全部为虚构演示数据。

## 全局约定
1. API 统一返回 `{"code": 0, "data": ..., "message": "ok"}`；出错时 `code` 非 0，`message` 为中文。错误码登记在 `server/docs/errors.md`。
2. 时间一律用 UTC ISO8601 存储和传输，界面按北京时间显示。
3. 手机号在列表、日志、非本人接口中脱敏为 `138****1234`。
4. 不加载任何外部资源（包括在线字体和 CDN）；字体使用系统字体栈，优先 Noto Sans SC、思源黑体、PingFang SC、Microsoft YaHei。
5. 三端的颜色、字号、圆角、状态标签按 `docs/design/README.md` 的设计规范实现，状态标签的文案和含义三端一致。
6. 每个子项目都有 README：启动命令、默认账号、已知问题。

## 默认账号
- 用户端：任意 11 位手机号 + 验证码 `123456`；种子数据中准备 2 个演示用户（带病程、报告和分析）。
- 后台：5 个角色各一个账号（运营编辑、临床审核、技术、合规、超级管理），TOTP 固定码 `123456`。账号密码写在 server/README.md。
